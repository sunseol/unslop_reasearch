# Unslop Challenge UX Wireframe v0.1

Unslop Challenge의 화면 흐름과 각 화면의 요소, 수집 데이터와의 대응을 정한다. 현재 결론은 한 세션에 문서 쌍 10개를 제시하고, 쌍마다 여섯 단계의 질문을 고정된 순서로 묻되 정답은 마지막에 공개하는 것이다. 화면 배치는 텍스트 와이어프레임이며 시각 디자인은 포함하지 않는다.

## 설계 원칙

- **질문 순서를 고정한다.** 추측 → 확신 → 선호 → 구간 선택 → 이유 → 정답 공개. 뒤로 가기는 막는다. 정답을 본 뒤의 판단은 편향되므로 수집하지 않는다.
- **A·B 위치는 매번 무작위다.** 같은 쌍이라도 참여자마다 위치가 다르며 `crowd_response.position`에 실제 위치를 기록한다.
- **정답 공개는 작성 주체를 보여 주되 품질과 분리해 설명한다.** ‘AI가 쓴 글이 더 나을 수도 있다’는 메시지를 이 화면에서 전달한다.
- **한 쌍에 1분 안팎.** 문서는 한 화면에 들어오는 길이(각 300~600자)로 고른다. 긴 문서는 Challenge가 아닌 전문 평가에서 다룬다.
- **모바일 우선.** 세로 화면에서 두 문서를 위아래로 배치하고, 넓은 화면에서는 좌우로 배치한다.
- **개인정보를 받지 않는다.** 이름·이메일을 요구하지 않는다. 결과 공유는 세션 코드로 한다.

## 화면 흐름

```text
S0 시작 ─▶ S1 문서 쌍 읽기 ─▶ Q1 추측 ─▶ Q2 확신 ─▶ Q3 선호
                ▲                                         │
                │                                         ▼
                │                             Q4 구간 선택 ─▶ Q5 이유
                │                                         │
                │                                         ▼
                └────── (다음 쌍, 최대 10회) ◀──── R 정답 공개
                                                          │
                                              (10쌍 완료) ▼
                                                      F 세션 결과 ─▶ 공유 / 다시 하기
```

## 화면별 와이어프레임

### S0 시작

```text
┌──────────────────────────────────────┐
│  Can You Spot the Slop?              │
│  AI 시대, 당신은 AI가 쓴 글을         │
│  구별할 수 있습니까?                  │
│                                      │
│  같은 주제로 쓴 두 글을 읽고          │
│  어느 쪽이 AI가 쓴 글인지,            │
│  어느 쪽이 더 좋은 글인지 골라 주세요. │
│  10쌍, 약 10분.                       │
│                                      │
│  [ 시작하기 ]                         │
│                                      │
│  응답은 익명으로 저장되며 문체 품질    │
│  연구 데이터로 사용됩니다. (자세히)    │
└──────────────────────────────────────┘
```

‘자세히’는 수집 항목과 사용 목적을 설명하는 페이지로 연결한다. 동의 없이 시작할 수 없다.

### S1 문서 쌍 읽기

```text
┌──────────────────────────────────────┐
│  3 / 10                     ●●●○○○○○○○│
│  과제: 신규 가입률 하락 원인 보고      │
│  독자: 사업부장                        │
├──────────────────────────────────────┤
│  A                                   │
│  ┌──────────────────────────────┐    │
│  │ 8월 신규 가입이 전월 대비 12% │    │
│  │ 감소했습니다. 모바일 가입 완료 │    │
│  │ 율이 61%에서 48%로 ...        │    │
│  └──────────────────────────────┘    │
│  B                                   │
│  ┌──────────────────────────────┐    │
│  │ 최근 신규 가입률이 감소하는    │    │
│  │ 추세를 보이고 있습니다. 이러한 │    │
│  │ 상황을 개선하기 위해 ...       │    │
│  └──────────────────────────────┘    │
│                                      │
│  [ 다 읽었어요 ]                      │
└──────────────────────────────────────┘
```

과제와 독자를 함께 보여 준다. 참여자의 선호와 구간 선택이 문서 목적에 비춘 판단이 되도록 하기 위해서다. 두 문서는 같은 `task_id`다.

### Q1 추측

```text
┌──────────────────────────────────────┐
│  어느 쪽이 AI가 쓴 글일까요?          │
│                                      │
│  [ A가 AI ]  [ B가 AI ]               │
│  [ 둘 다 AI ] [ 둘 다 사람 ]           │
└──────────────────────────────────────┘
```

`source_guess`에 A·B 각각 `ai`/`human`으로 저장한다. 네 선택지를 두는 이유는 `pair_kind`에 human-human, ai-ai 쌍이 섞여 있기 때문이다.

### Q2 확신

```text
┌──────────────────────────────────────┐
│  얼마나 확신하세요?                   │
│                                      │
│  ( 찍었다 ) ( 약간 확신 )             │
│  ( 꽤 확신 ) ( 확실하다 )             │
└──────────────────────────────────────┘
```

`confidence`: `guess`, `slight`, `fairly`, `certain`.

### Q3 선호

```text
┌──────────────────────────────────────┐
│  사업부장이 읽는다면                  │
│  어느 글이 더 좋은가요?               │
│                                      │
│  [ A가 낫다 ] [ B가 낫다 ] [ 비슷하다 ]│
└──────────────────────────────────────┘
```

질문 문구에 독자를 넣는다. `preference`: `A`, `B`, `similar`.

### Q4 구간 선택

```text
┌──────────────────────────────────────┐
│  AI스럽거나 불필요하다고 느낀 부분을   │
│  눌러서 표시해 주세요. (없으면 건너뛰기)│
├──────────────────────────────────────┤
│  A                                   │
│  8월 신규 가입이 전월 대비 12% 감소   │
│  했습니다. ...                        │
│  B                                   │
│  최근 신규 가입률이 감소하는 추세를    │
│  보이고 있습니다. [이러한 상황을 개선  │
│  하기 위해 다양한 관점에서 원인을 분석 │
│  하고] ...                            │
│                                      │
│  선택 2개              [ 건너뛰기 ] [ 다음 ]│
└──────────────────────────────────────┘
```

선택 단위는 문장이다. 문장을 누르면 선택·해제되고, 두 문서 모두에서 고를 수 있다. 문장 경계는 서버에서 미리 나누어 `start`·`end` 좌표로 저장하므로 `selected_spans`는 [데이터 Schema](../03_데이터와_평가/데이터_Schema.md)의 구간 형식과 같다. 단어 단위 선택은 모바일에서 오조작이 많아 첫 버전에서 제외한다.

### Q5 이유

```text
┌──────────────────────────────────────┐
│  왜 그렇게 느꼈나요? (복수 선택)       │
│                                      │
│  [ ] 장황하다        [ ] 추상적이다    │
│  [ ] 뻔한 표현이다   [ ] 반복적이다    │
│  [ ] 과하게 설명한다 [ ] 번역체 같다   │
│  [ ] 문장 구조가 AI스럽다              │
│  [ ] 기타: ______________             │
│                                      │
│  [ 다음 ]                             │
└──────────────────────────────────────┘
```

Q4에서 건너뛰었으면 이 화면도 건너뛴다. `categories`는 참여자의 인상으로 보관하며 Taxonomy 유형으로 변환하지 않는다.

### R 정답 공개

```text
┌──────────────────────────────────────┐
│  정답                                 │
│                                      │
│  A: 사람이 썼습니다   B: AI가 썼습니다 │
│  당신의 추측: B가 AI  ✔               │
│                                      │
│  참여자 68%가 A를 더 좋은 글로 골랐어요.│
│                                      │
│  누가 썼는지와 글이 좋은지는 다른      │
│  문제입니다. 사람이 쓴 글에도, AI가    │
│  쓴 글에도 빈 표현과 반복은 생깁니다.  │
│                                      │
│  [ 다음 쌍 ]                          │
└──────────────────────────────────────┘
```

참여자 통계는 해당 쌍의 응답이 30건 이상일 때만 보여 주고, 그 전에는 문구를 숨긴다. human-human, ai-ai 쌍에서는 ‘둘 다 사람이 썼습니다’처럼 표시한다. 전문 평가자의 판정 결과는 첫 버전에서 보여 주지 않는다. Gold가 아직 없기 때문이다.

### F 세션 결과

```text
┌──────────────────────────────────────┐
│  10쌍 완료                            │
│                                      │
│  작성 주체 맞힌 비율   6 / 10         │
│  확신했을 때 정답률    2 / 4          │
│  다른 참여자 평균      5.4 / 10       │
│                                      │
│  당신이 더 좋다고 고른 글 중          │
│  AI가 쓴 글: 4개                      │
│                                      │
│  [ 결과 공유 ]  [ 다시 하기 ]          │
│  [ Unslop 소식 받기 ]                 │
└──────────────────────────────────────┘
```

‘소식 받기’는 별도 페이지로 이동하며 이메일을 받는다. Challenge 응답과 연결하지 않는다. 공유 카드에는 맞힌 비율과 세션 코드만 넣는다.

## 데이터 대응

| 화면 | 저장 필드 | 비고 |
|---|---|---|
| S1 | `pair_id`, `position`, `timings_ms.read` | 읽기 시작부터 ‘다 읽었어요’까지 |
| Q1 | `source_guess`, `timings_ms.q1` | |
| Q2 | `confidence` | |
| Q3 | `preference` | |
| Q4 | `selected_spans` | 건너뛰면 빈 배열 |
| Q5 | `categories`, `other_text` | |
| R | `revealed: true` | 도달하지 못한 응답은 `false`로 남기고 집계에서 구분 |

한 쌍의 응답은 R 도달 시점에 저장한다. 중간 이탈 응답은 Q1까지 답했으면 `revealed: false`로 저장한다.

## 쌍 배정 규칙

- 세션의 10쌍은 서로 다른 `task_id`에서 고른다.
- `pair_kind` 비율은 human-ai 7, human-human 1~2, ai-ai 1~2로 시작한다. 비율은 응답 분포를 본 뒤 조정한다.
- 응답 수가 적은 쌍을 우선 배정해 쌍별 응답 수를 고르게 한다.
- 같은 세션 코드로 다시 하기를 누르면 이전에 본 쌍은 제외한다.

## 근거

[사업계획서](../unslop_business_plan.md) 6.2절 사용자 경험, 6.3절 질문 순서와 편향 방지 이유, 6.4절 수집 데이터 항목을 화면으로 옮겼다. 네 가지 추측 선택지, 문장 단위 구간 선택, 정답 화면의 작성 주체·품질 분리 메시지, 통계 표시 최소 응답 수 30건은 이 문서의 제안이다.

## 미결 사항

- **세션 식별 방식:** 쿠키와 세션 코드 중 무엇으로 반복 참여를 구분할지 [데이터 Schema](../03_데이터와_평가/데이터_Schema.md)의 미결 사항과 함께 정한다.
- **문장 분리 규칙:** 한국어 문장 경계 처리(따옴표, 목록 항목, 줄바꿈)를 정하지 않았다. 첫 구현에서 규칙을 만들고 오분리 사례를 모은다.
- **접근성:** 화면 낭독기에서 문장 선택 UI가 동작하는 방식을 정하지 않았다.
- **첫 공개 시 쌍의 수:** Raw Corpus 생성 규모에 따라 정한다. 최소 30쌍은 있어야 세션 간 중복이 적다.
